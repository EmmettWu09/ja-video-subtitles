# Design: add-config-fallback-for-all-cli-options

## Context

现有 `cli.py` 在 argparse 阶段要求输入和 `-o`，`--force`、`--yes` 使用 `store_true` 的 `False` 默认值；这些行为无法区分「用户未传」和「用户明确关闭」。`cmd_run` 在读取配置前访问输入路径，`cmd_burn` 在预检加载配置前进行字幕映射。词汇参数已通过 `None` 区分未传，并在预检中覆盖配置。

`config.py` 将完整流水线配置与独立烧录配置分开；配置定位固定在项目根目录。设计沿用这两点，动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 在访问输入、选择字幕、创建输出目录及执行预检之前生成一次最终有效选项，供整个命令使用。
- 在解析层保留「未指定」信息，避免默认值或真值判断掩盖配置以及显式 `false`。
- 用单一映射保留现有配置命名，避免相同选项出现多个互相竞争的配置键。

**Non-Goals:**

- 不增加配置文件选择、环境变量业务参数、配置继承、profile 或默认子命令。
- 不将现有仅配置能力反向扩展为新的业务 CLI 参数；新增否定开关仅为覆盖配置布尔值。
- 不调整 `download` 的模型加载或失败回退策略，不改变模型下载、媒体处理和词汇算法。

## Decisions

### 1. 按命令保存参数，词汇配置保持原位

全部映射如下。表中的必需项表示最终有效值必需，不表示命令行必填。

| 命令 | CLI 参数 | TOML 键 | 类型 | 两处均未提供时 |
| --- | --- | --- | --- | --- |
| `run` | 位置参数 `input` | `run.input` | 非空路径字符串 | 报缺少输入 |
| `run` | `-o/--output-dir` | `run.output_dir` | 非空路径字符串 | 报缺少输出目录 |
| `run` | `--vocab-output-dir` | `vocabulary.output_dir` | 路径字符串 | 空字符串，跟随有效主输出目录 |
| `run` | `--vocab-format` | `vocabulary.format` | `md/json/both` | `both` |
| `run` | `--force/--no-force` | `run.force` | 布尔 | `false` |
| `run` | `-y/--yes/--no-yes` | `run.yes` | 布尔 | `false` |
| `burn` | 位置参数 `inputs` | `burn.inputs` | 非空路径字符串数组 | 报缺少输入 |
| `burn` | `-o/--output-dir` | `burn.output_dir` | 非空路径字符串 | 报缺少输出目录 |
| `burn` | `-s/--subtitles` | `burn.subtitles` | 路径字符串，可为空 | 无显式字幕文件 |
| `burn` | `--subtitle-dir` | `burn.subtitle_dir` | 路径字符串，可为空 | 在有效主输出目录匹配 |
| `burn` | `-y/--yes/--no-yes` | `burn.yes` | 布尔 | `false` |

`download` 无业务参数，继续复用 `[asr] model_id`。子命令名称、`-h/--help`、`--version` 是调用控制，不配置。`run` 和 `burn` 不互相继承输入、输出或覆盖选项；没有新增共享默认段，避免出现第四层优先级。所有既有 `[deepseek]`、`[asr]`、`[prompt]`、`[style]`、`[video]`、`[vocabulary]` 的合法配置继续可用。

示例配置的目标形态如下；实际模板中输入、输出和字幕路径保持注释，防止复制后启用示例路径。

```toml
[run]
# input = "videos"
# output_dir = "out"
force = false
yes = false

[burn]
# inputs = ["video.mp4", "more-videos"]
# output_dir = "burned"
# subtitles = "edited.srt"  # 仅用于展开、去重后单视频；不要同时设置 subtitle_dir
# subtitle_dir = "subtitles"
yes = false

[vocabulary]
output_dir = ""  # 跟随本次有效主输出目录
format = "both"
```

### 2. 先解析显式参数，再形成命令有效选项

入口流程为：解析 CLI → 读取 TOML → 校验当前命令作用域内已配置字段 → 合并显式 CLI 与配置、默认值 → 校验最终必需项和来源互斥 → 展开有效路径并收集、去重视频 → 检查显式单字幕只对应一个视频 → 进行既有字幕映射、预检、目标冲突检查和处理。

argparse 将 `run.input` 改为可选位置参数、`burn.inputs` 改为零个或多个位置参数，`-o` 移除解析阶段 `required=True`。对标量使用 `None` 或显式缺省标记；`burn.inputs` 的零个参数表示未提供。有位置参数时整组替换配置数组，保持原有输入顺序，不追加配置中的视频。

建议在配置层定义按命令的有效选项结构及共享解析入口。业务配置和命令选项可以分开建模，但预检与命令处理必须复用同一次加载结果，不再次读取配置或用 argparse 原值替换已合并字段。`Path(...)` 只能接收完成合并和校验的路径。

选择集中解析而非各阶段自行回退，使词汇目录、字幕默认目录、日志、报告、覆盖检查与实际处理使用同一输出目录。帮助和版本请求由 argparse 直接结束，不读取配置或访问 API。

### 3. 布尔值保留三态，明确 force 与 yes 的关系

`--force`/`--no-force` 和 `--yes`/`--no-yes` 分别构成互斥选项组；`-y` 为 `--yes` 的别名。未指定为 `None`，显式开启为 `True`，显式关闭为 `False`。同一开关正反同时出现报参数错误，不采用最后出现者获胜的隐式规则。

合并时用「是否指定」判断，不能用 `cli_value or config_value`。`run` 最终 `force=true` 仍表示全部重跑并自动覆盖，因此自动确认条件为有效 `yes OR force`；`burn` 仅取有效 `yes`。`--no-yes` 不抵消仍开启的 `force`，`--no-force` 也不抵消仍开启的 `yes`；恢复交互且保留产物复用时可同时传入两个否定开关。

仅将 `store_true` 默认值改为 `None` 不足以关闭配置中的 `true`，因此增加显式否定参数。

### 4. 字幕来源以互斥组为单位选择

优先级按「CLI 字幕来源组 → 配置字幕来源组 → 有效输出目录」执行。CLI 指定 `-s` 或 `--subtitle-dir` 时，配置的两个来源都不参与选择；CLI 自身同时给出两者仍报错。CLI 没有指定来源时，配置中非空的 `burn.subtitles` 与 `burn.subtitle_dir` 不得同时存在。选定单字幕文件后，沿用展开并去重后恰有一个视频的限制。

例如，配置为 `burn.subtitle_dir="subs"` 时，`burn clip.mp4 -s edited.srt` 使用 `edited.srt`；配置为 `burn.subtitles="old.srt"` 时，`burn videos --subtitle-dir new-subs` 使用目录映射。无显式来源时，在最终输出目录查找 `<stem>.bilingual.srt`。

不逐字段拼接来源，是为了避免用户通过 CLI 切换模式后仍与配置中的另一种模式发生冲突。配置组存在双来源冲突但被一个合法 CLI 来源整体覆盖时，采用 CLI 来源；配置字段类型错误仍按下一节处理。

### 5. 保留配置严格校验与命令隔离

沿用既有词汇规则：配置本身先通过当前作用域的类型和取值校验，再接受 CLI 覆盖。`force/yes` 仅接受 TOML 布尔值，拒绝 `0/1` 或字符串；`burn.inputs` 仅接受非空数组且每项为非空字符串；必需路径不接受空串、纯空白或 NUL。词汇目录和可选字幕来源配置仅允许精确空字符串表示使用默认目录/来源，非空但纯空白的字符串无效；显式 CLI 路径不接受空字符串、纯空白或 NUL（U+0000）。合法路径内容不自动裁剪。

类型和取值校验与文件系统校验分开：被覆盖配置必须是合法路径字符串，但不要求对应文件存在，也不创建旧目录。仅对最终选中的路径检查存在性、格式、可写性和输入输出冲突；互斥组的组合校验在选择有效来源之后执行。未知配置键继续沿用现有处理，不在本变更新增全面 schema 拒绝规则。

`run` 校验 `[run]` 及现有流水线配置，忽略 `[burn]`；`burn` 只读取 `[burn]`、`[style]`、`[video]`，忽略其他可解析配置段。任何 TOML 语法损坏仍报错。`run` 保持必须有配置文件及有效 API key，`burn` 无配置时仍可使用完整 CLI 与默认样式/码率。

所有业务路径在选择后展开 `~`，相对路径以执行时 cwd 为基准；配置文件本身仍从项目根目录读取。配置数组不进行 shell 分词、通配符或环境变量替换。参数、配置、必需项或组合错误均以退出码 2 结束，提示命令选项或配置字段；在此之前不调用 API、不下载模型、不创建输出目录或修改媒体。

### 6. 文档展示使用方式并保持旧用法

CLI 帮助和三种语言 README 同步提供完整映射、纯配置启动、局部 CLI 覆盖、关闭配置开关及字幕来源切换示例。示例配置保留安全的 `force=false`、`yes=false`，同时说明显式配置为 true 将产生与相应 CLI 开关相同的重跑和覆盖行为。既有完整 CLI 不要求迁移；既有配置省略新段时行为与过去一致。

## Risks / Trade-offs

- 配置开启 `force` 或 `yes` 后，短命令也会重跑或自动覆盖 → 默认保持 false，帮助和模板说明含义，并提供否定开关。
- 放宽 argparse 必填约束可能让缺省值进入路径处理 → 在任何路径使用或预检副作用前集中校验最终必需项，测试空参数启动。
- 先校验配置意味着 CLI 无法掩盖当前命令配置中的类型错误 → 保持既有词汇契约，错误指出完整字段名；未选路径不做文件系统检查。
- 同一配置有不同命令的输入或目录，可能误合并 → 独立命令作用域，覆盖列表与字幕来源采用整体替换，并测试互相隔离。
- 调整预检参数传递可能影响既有词汇回退和 burn 独立性 → 保留对应回归，并用离线 CLI 集成测试验证最终传入值。

## Migration Plan

1. 实现配置解析、类型校验、有效选项结构及单元测试，再调整 CLI 和预检调用次序。
2. 接入最终目录、覆盖和字幕来源，保留现有处理、路径冲突及退出码规则。
3. 更新模板和帮助；新增字段均为可选，不修改用户现有 `config.toml`。
4. 完成离线回归和 OpenSpec strict 校验后再按实施流程交付；本次仅创建规划文档。

回退代码时删除新增配置段或恢复显式位置输入、`-o` 及已有正向开关。既有领域配置和媒体产物不需要迁移。
