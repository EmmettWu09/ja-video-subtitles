# Design: add-standalone-burn-command

## 命令接口

```bash
# 使用输出目录中已有的 video.bilingual.srt
./ja-video-subtitles burn video.mp4 -o out

# 指定单个字幕文件，可采用任意文件名
./ja-video-subtitles burn video.mp4 -s edited.srt -o out

# 多个视频按主干名匹配字幕
./ja-video-subtitles burn first.mp4 second.mov -o out
./ja-video-subtitles burn first.mp4 second.mov --subtitle-dir subtitles -o out -y

# 文件夹与文件可混合，文件夹仅展开当前层
./ja-video-subtitles burn videos/ extra.mov --subtitle-dir subtitles -o out
```

位置参数接受一个或多个路径。`-o/--output-dir` 必填；`-s/--subtitles` 与 `--subtitle-dir` 互斥。`-s` 仅在全部输入展开、去重后恰有一个视频时可用，因此单视频文件夹及重复指定同一视频也可使用。`-y/--yes` 自动覆盖已有成片；`burn` 不提供 `--force`，因为没有可重跑的前置字幕阶段。

## 输入展开与映射

按命令行输入顺序扫描路径；显式文件必须存在且扩展名为 mp4/mov（不区分大小写）。目录按文件名排序，收集当前层匹配的文件，忽略子目录和其他格式。以解析后的源路径去重，保留首次出现顺序。任一显式指定的目录在当前层没有 mp4/mov 时，拒绝整批请求，即使其他输入有效；最终没有视频时同样报错。

每个视频映射为一个烧录任务：

| 字段 | 来源 |
|---|---|
| video | 展开并去重后的源视频 |
| subtitles | 显式 `-s`，或 `<subtitle-dir>/<stem>.bilingual.srt`，或默认 `<out>/<stem>.bilingual.srt` |
| output | `<out>/<stem>.sub.mp4` |

不同视频的主干名不区分大小写比较，并归一化 Unicode；若冲突，在任何烧录前拒绝整批请求，避免不同输入写到同一个字幕映射或成片。每个成片、日志和报告目标都与全部源视频、输入字幕及其他输出比较实际路径和已有文件身份，拒绝覆盖任一输入或输出目标互相冲突的情况，包括符号链接或硬链接别名。即使指定 `-y`，也不得绕过源文件保护。

在烧录第一条任务前完成全部字幕映射校验：字幕必须是可读 UTF-8（可含 BOM）、可解析且非空的 SRT。任何映射失败都以退出码 2 结束，不得烧录前面的有效任务，也不得隐式生成或修复字幕。字幕内容由用户提供，不强制必须为双语。

## 配置与依赖边界

`run` 保留完整配置与预检行为。`burn` 使用独立加载入口：项目根目录没有 `config.toml` 时使用字幕样式与视频码率默认值；文件存在时读取相关配置，缺少或为空的 DeepSeek key 不阻塞。无法解析的 TOML 或非法烧录配置在处理前给出错误。

`burn` 的预检仅覆盖 macOS 平台、实际烧录所需 Python 依赖、ffmpeg/libass 与 ffprobe、磁盘空间（至少去重视频总大小的 2 倍）、输出目录创建与可写性。不得检查或初始化 ASR 模型、翻译 client 或 API 连通性。继续复用 `h264_videotoolbox`、音频直通、现有字幕样式和烧录进度。

## 路径字符处理

视频、字幕及输出路径允许空格、中日韩字符、单引号、方括号、冒号和反斜杠。用户仅需按所用 shell 的规则引用参数；内部用独立 subprocess 参数传递路径。字幕路径嵌入 ffmpeg `subtitles` 滤镜时，分别处理滤镜选项值与滤镜图两层转义，不能只做 shell 转义或用单引号包裹。此修复位于共用烧录路径，`run` 和 `burn` 均受益。

## 执行、覆盖与报告

执行次序为：输入展开与安全校验 → 字幕映射与完整校验 → 烧录配置/预检 → 全批次同名成片确认 → 串行烧录 → 汇总及报告。

已有成片统一在实际烧录前确认。用户拒绝或 stdin EOF 时标记 skipped，`-y` 自动允许覆盖。烧录期间没有交互。每个视频只执行 burn 阶段；不读取或修改 `.ja.srt`、`.zh.srt`，不重建 `.bilingual.srt`。

复用 `run.log` 追加记录与 `report-<timestamp>.md` 报告。报告列出实际字幕输入、成片、烧录耗时和错误；以 burn-only / N/A 明确模型、翻译服务以及未运行阶段不适用，不得把它们显示为已执行。报告不包含密钥。

退出码约定：

- `0`：所有任务成功或按用户选择跳过（包括全跳过）。
- `1`：至少一个视频烧录失败；记录错误并继续其余视频。
- `2`：参数、输入、字幕映射、安全检查、配置或预检失败；没有视频开始烧录。

Ctrl+C 沿用既有烧录中断与半成品清理机制，不开始后续任务。

## 验证策略

- 离线 CLI 测试验证单文件默认/显式字幕、多文件与文件夹组合、目录排序、空目录拒绝整批、路径去重及同名冲突。
- 验证多视频搭配 `-s`、互斥选项、缺失/空/无效/非 UTF-8 字幕，在任何任务烧录前失败。
- 验证输出目标与任一源文件直接重合、符号链接或硬链接别名均被拒绝，`-y` 不例外。
- 验证缺少配置、无效 API key、ASR 未下载时烧录无需网络；独立预检仍能发现烧录依赖、磁盘及写权限问题。
- 验证提前覆盖确认、EOF 跳过、自动覆盖、失败继续与退出码；确认报告仅反映实际烧录步骤。
- 运行既有测试防止 `run` 回归；用本机 ffmpeg 生成小样本进行烧录检查，无需外部视频、API 或 ASR。
- 对含空格、中日韩字符、单引号、方括号、冒号和反斜杠的字幕路径进行滤镜转义测试，并用真实 ffmpeg 验证这些路径可以完成烧录。
