# Design: add-configurable-vocabulary-output-and-mp3

## Context

现有流水线在翻译后生成词汇 Markdown 和 JSON，随后合成字幕并烧录。所有路径由 `-o` 和视频主干名拼接，词汇复用要求两种文件同时有效；仅 JSON 承载结构化元数据。覆盖确认只检查成片，报告也以固定目录列举产物。

本次将词汇的内容选择与文件交付方式分开，并在完整流水线增加本地 MP3。既有字幕命名、词汇内容、独立 `burn` 入口以及 API 使用范围继续沿用。

## Goals / Non-Goals

**Goals:**

- 每次运行可独立选择词汇目录以及 `md`、`json`、`both` 三种模式。
- 保持默认路径与默认双格式行为兼容；新配置与参数能明确覆盖、校验并报告。
- 单格式运行只写对应公开文件，也能可靠续跑。
- 将源视频第一条音轨导出为与成片同目录、同主干名的 MP3。
- 在开始处理前解决覆盖选择；导出失败不损坏旧文件或阻止剩余视频。

**Non-Goals:**

- 不新增独立音频命令、音轨选择、音频剪辑或格式/码率参数。
- 不移动或清理以往运行遗留的词汇文件。
- 不改变 `burn` 的输入、依赖及单纯烧录语义。
- 不改变词汇抽取、JLPT 判级、释义 API 或字幕内容。

## Decisions

### 1. 输出选项在流水线入口统一解析

`[vocabulary]` 新增 `output_dir = ""` 和 `format = "both"`。`output_dir` 只接受字符串；空字符串表示回退到 `-o`，非空值及 `--vocab-output-dir` 都以当前工作目录为相对基准。`format` 只接受 `md`、`json`、`both`。CLI 显式值优先于配置默认值，但配置本身仍需通过字段类型与枚举校验。

入口统一获得有效目录和格式，随后把明确路径传给词汇阶段和报告，避免模块各自推导路径。启用词汇时提前创建和检查有效词汇目录；禁用时不触及该目录。`burn` 不解析这些参数、不验证词汇配置。

选择复用 `[vocabulary]` 配置而不增加独立顶层输出配置，因为目录和格式只控制词汇产物，语义集中且能与现有启用开关联动。

### 2. 按选中格式写入、校验并报告

词汇阶段仍构造同一份结构化结果，并按模式生成 `<stem>.vocab.md`、`<stem>.vocab.json` 中的所选文件。每个正式文件通过同目录临时文件与原子替换写入；两文件模式保持内容一致性检查。

Markdown-only 在文件末尾追加带版本的 HTML 注释，保存 base64 编码的完整结构化文档；复用时验证文档及其对应的渲染内容，覆盖源字幕哈希、学习者设置、JLPT 数据与形态分析版本，而不创建 JSON sidecar。JSON-only 使用既有 JSON 元数据。所选文件缺失、损坏或格式切换时，可从同目录内新鲜有效的 JSON 或嵌入 Markdown 的文档补齐所选文件；多个候选均有效时优先采用生成时间较新的文档，避免旧的未选格式覆盖新词义，并避免重复调用 API；仅在内容缓存过期或不可用时重新提取。未选文件不作为必需的复用条件或产物清单来源。旧双格式文件允许被识别和继续复用；`--force` 始终重新生成所选格式。

切换目录后仅考察新目录中的缓存及所选产物；不搜索或移动旧目录内容。切换格式时保留旧文件，报告仅列所选文件，避免把用户历史文件删除或误报为本次结果。

### 3. MP3 从源视频第一条音轨导出

新增音频导出模块，复用 ffmpeg/ffprobe 的发现和探测函数。输入为源视频，显式选择第一条音轨并关闭视频输出，通过 `libmp3lame` 以 192 kb/s 转码为可播放的 MP3。`run` 预检该编码器，`burn` 不增加此检查。输出为 `-o/<stem>.mp3`，独立于词汇目录。

正式输出在临时 MP3 导出且 ffmpeg 正常退出后才原子替换；ffmpeg 失败、没有音轨或中断时清理临时文件，终止仍运行的子进程，并保留此前正式 MP3。成功导出记录音频阶段耗时和产物；不把非空文件简单视为已经成功导出。

音频阶段属于 `run`，在字幕成片成功后导出；若词汇阶段失败但成片成功，仍尝试音频。成片已成功而音频失败时保留成片，视频标记 `partial`，记录错误并继续剩余视频。烧录失败仍按既有主流水线失败语义处理。

### 4. 批次开始前处理视频与音频覆盖

对每个视频同时检查成片和 MP3。任一目标已存在且没有 `-y/--yes` 或 `--force` 时，在全部处理之前提示覆盖或跳过该视频；跳过保留两个目标。EOF 按跳过处理。确认覆盖后音频重新从源视频导出，避免把旧 MP3 无条件当作新结果。

成片、MP3 及所选词汇目标均纳入输出冲突检查，拒绝规范化后主干名相同的不同输入，避免批次内相互覆盖。`burn` 仍只检查成片。

### 5. 报告使用实际选择与阶段结果

配置摘要加入有效词汇输出目录和格式；每个视频记录所选词汇路径，产物清单以这些路径为准，允许词汇文件位于 `-o` 之外。词汇禁用时不列历史词表。完整流水线记录音频阶段耗时、成功 MP3 路径和失败原因；导出失败时即使保留旧 MP3，也不把它列为本次成功音频。词汇与音频同时失败时保留两个错误；独立烧录报告不出现未执行的音频阶段。

音频失败与已有词汇阶段失败一样使用 `partial`；批次中存在 `partial` 或 `failed` 时退出码为 1，参数/配置/预检错误为 2，全部成功或跳过为 0。

## Risks / Trade-offs

- Markdown-only 的复用需要嵌入元数据。元数据放在隐藏注释中，不影响正常阅读；缺失或被手工改坏时安全重建。
- 双格式写入无法跨两个文件做到单个文件系统事务。保留逐文件原子替换，并用续跑的一致性校验发现中断后不匹配的文件。
- 格式或目录切换会留下历史产物。保留它们避免意外删除；README 明确说明所选模式只控制当前运行的生成和报告。
- MP3 编码依赖本机 ffmpeg 的音频编码器。测试覆盖正常转码与没有音轨、编码失败、中断等路径；失败需显示明确原因并保留已经完成的成片。

## Migration Plan

1. 新增配置默认值和参数，旧配置文件无需迁移。
2. 扩展词汇输出与新鲜度校验，支持旧双格式缓存。
3. 接入 MP3、冲突确认、报告及文档。
4. 运行离线回归、真实 ffmpeg 小样本导出检查和 OpenSpec strict 校验。

## Open Questions

无。采用 `run` 默认生成 MP3，文件名为 `<stem>.mp3`；默认词汇输出维持两种格式并跟随 `-o`。
