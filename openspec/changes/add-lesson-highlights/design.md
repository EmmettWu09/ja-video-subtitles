# Design: add-lesson-highlights

## Context

现有 `run` 流水线依次执行转写、翻译、词汇、双语合成、烧录和 MP3 导出，产物全部写入 `-o` 目标目录，并具备预检、覆盖确认、断点复用和运行报告机制。需求文档《日语课堂高光视频生成设计》描述了一个独立的 lesson-video 工具：从课堂录屏和日中双语 SRT 产出课堂总结、独立高光切片集和 3–5 分钟精华视频，片头用本地配音替换原音轨，分析仅上传字幕文本。

本次把该能力作为 `run` 的可选末尾阶段接入：流水线自己生成的日中字幕恰好满足设计文档推荐的「未烧录原片 + 外部 SRT」输入形态，可直接复用既有配置（DeepSeek API、ffmpeg、样式）、批量执行与报告框架。

## Goals / Non-Goals

**Goals:**

- `run` 默认生成高光：课堂总结 `summary.md`、独立切片集 `clips/`、精华视频 `highlights.mp4`、配套 SRT、分析与计划 JSON、回看目录 `index.html`，全部位于 `<out>/<stem>.highlights/`。
- 通过 `--highlights` / `--no-highlights` 与 `[highlights] enabled` 控制开关，默认开启，遵循既有布尔合并与正反互斥规则。
- 精华版片头：原片开头连续画面（起点可配置）+ 本地日文摘要配音（15–25 秒）+ 摘要日中双语字幕，原音轨完全不进入片头。
- 高光选取受字幕证据约束，保留真实表现（不删停顿制造流利、不错接表扬），不设固定数量上限。
- 阶段级断点恢复；阶段级失败标记 `partial`，不影响已完成的字幕成片，批次继续。
- 分析请求只包含字幕文字、编号、时间及衍生文本；音视频处理全部留在本机。

**Non-Goals:**

- 不支持已烧录双语字幕原片（`burned-bilingual`）作为高光输入，不实现原字幕区域遮盖；`burn` 命令不生成高光。
- 不提供计划编辑后独立重渲染命令（设计文档的 `render --plan`），调整高光需重跑高光阶段。
- 不支持多音轨选择、师生独立音轨合并与自定义字幕样式参数；高光切片沿用既有烧录样式。
- 不做发音、流利度等语音层面评价；静音检测仅用于辅助寻找自然剪辑边界。
- 不改变转写、翻译、词汇、烧录与 MP3 导出阶段的行为。

## Decisions

### 1. 高光作为 `run` 的末尾可选阶段，而非独立命令

设计文档以独立 CLI 描述，但本项目的 `run` 已产出与录屏同步的 `<stem>.ja.srt`/`<stem>.zh.srt`，并具备输入检查、预检、批量、覆盖确认和报告能力。作为 `run` 阶段接入可避免重复实现整条输入链路，且天然满足设计文档中 `source_subtitles=none` 的推荐路径：课堂高光从**源视频**（未烧录）剪辑，并烧录流水线生成的双语字幕，而不是从已烧录的 `<stem>.sub.mp4` 二次剪辑。

高光阶段在烧录成功后执行，与 MP3 导出同级；词汇或音频阶段失败（视频已为 `partial`）不阻止高光阶段尝试。

### 2. 高光产物固定在目标目录的 `<stem>.highlights/` 子目录

满足「高光生成放在目标目录」的要求，与既有「全部产物写入 `-o`」的语义一致；批量运行时按视频主干名分子目录，避免冲突。内部采用设计文档的布局：

```text
<out>/<stem>.highlights/
  summary.md            # 课堂总结
  index.html            # 回看目录
  highlights.mp4        # 精华视频
  clips/clip-001.mp4 …  # 独立高光切片
  subtitles/highlights.srt
  subtitles/clips/clip-001.srt …
  analysis/transcript.json   # 规范化字幕
  analysis/candidates.json   # 候选与取舍理由
  plans/clips.json           # 独立切片清单
  plans/highlights.json      # 精华编排清单（唯一成片时间轴）
  state.json                 # 阶段状态与缓存键
  report.json                # 高光检查报告
```

`subtitles/` 独立存放是为降低播放器自动加载外挂字幕造成重复显示的概率；`index.html` 明确提示「视频已含字幕，观看时关闭外挂字幕」。

### 3. 默认开启，正反开关与既有布尔规则一致

`[highlights] enabled` 默认 true，即默认生成高光；`--no-highlights` 临时关闭，`--highlights` 显式开启，正反开关互斥（同时出现退出码 2）。解析顺序沿用「显式 CLI → 配置 → 内置默认值」。关闭时：不创建高光目录、不执行高光阶段、跳过 `say`/音色预检、报告不显示高光阶段。

其余高光参数（`target_seconds`、`intro_start_seconds`、`ja_voice`、`zh_voice`）仅提供配置项，不增加 CLI 参数，控制参数面膨胀；字幕整体偏移在 `run` 场景无意义（字幕由流水线自生成并与视频同步），故不引入 `subtitle_offset_ms`。

### 4. 高光阶段非阻塞，失败降级保留已完成产物

与词汇、音频阶段一致：高光阶段的阶段级异常记录为 `partial`，不否定已完成的字幕成片，批次继续处理其余视频。阶段内部进一步降级：精华版合成（片头配音、编排渲染）失败时，已完成的课堂分析、独立切片及其 SRT 仍然保留并在报告与回看目录中标注精华版未完成；不自动改用中文片头或省略片头凑出成片。

### 5. 模型只引用字幕编号，时间由程序映射

课堂分析按约 5 分钟分块、保留约 30 秒上下文重叠，从**原始字幕**发现话题与高光候选，不得以压缩后的章节摘要代替原文做高光发现。模型返回结构化 JSON（候选类型、字幕编号区间、推荐理由、所需上下文），SHALL NOT 接受模型生成的时间码；程序本地校验编号引用存在、区间有效，再映射为真实时间。空响应、截断或结构非法按失败处理，限定重试最多 2 次，保留原始响应。跨块候选经证据复核、合并与去重后形成高光清单；证据不足的候选进入待复核清单，不进入精华版。

### 6. 片头只含本地配音，原音轨完全移除

日文摘要与中文串联使用 macOS 本地 `say` 合成（默认 `Kyoko` / `Tingting`，可配置）。片头画面为原片开头连续画面（默认源起点 00:00，`intro_start_seconds` 可调整），输出音轨只含摘要配音，不做语音分离或降噪。片头含句间停顿 15–25 秒并计入精华版总时长；超出 25 秒时先精简文本再重新合成，不得加速语音或挤压字幕阅读时间。课堂原声与 TTS 做响度匹配。预检在启用高光时检查 `say` 命令与配置音色存在。

### 7. 唯一成片时间轴与字幕裁定

`plans/highlights.json` 是渲染、烧录和 SRT 导出的共同依据，源素材时间与成片时间分离，内部统一毫秒。每条保留字幕先与裁定后的源区间求交集再转换：`成片字幕时间 = 裁定后源字幕时间 − 片段源起点 + 片段在成片中的起点`，禁止负时间、零时长或跨越片段边界。各段位置以实际生成媒体的时长累计，画面、音轨、字幕共用同一套边界。片头区间的新 SRT 只记录摘要内容。独立切片与精华版分别维护时间轴，精华版直接从源素材剪辑，不从已压缩的独立切片二次剪辑。

### 8. 断点恢复与缓存键

`state.json` 记录各阶段（字幕整理、课堂分析、全局筛选、边界确定、切片导出、精华编排、配音、合成、检查）的完成状态与缓存键。缓存键包含：源视频与双语字幕内容哈希、翻译模型名称、`ja_voice`/`zh_voice`、`target_seconds`、`intro_start_seconds` 及提示词版本。任一变化仅重跑受影响阶段及下游；`--force` 重跑全部高光阶段。不得复用与当前输入不一致的计划或配音。已有 `highlights.mp4` 与 `<stem>.sub.mp4`、`<stem>.mp3` 一样纳入处理前的统一覆盖确认。

## Risks / Trade-offs

- **默认开启改变既有行为**：既有用户下次 `run` 会多出高光产物与耗时。缓解：README 与 CLI 帮助显著说明，提供一键关闭；高光失败仅为 `partial`，不阻断字幕主产物。
- **真实 SRT 配对差异**：日语与中文的配对、断句格式以首份真实素材为准。缓解：解析失败明确报告，不按字符外观猜测语言归属；日中含义冲突、异常断句做标记而非擅自修正。
- **长视频分析成本与稳定性**：约 50 分钟字幕分块调用模型，可能空响应或截断。缓解：分块 + 重叠、结构校验、限定重试、阶段缓存。
- **TTS 音色缺失**：`Kyoko`/`Tingting` 在某些系统不可用。缓解：预检明确报错并提示更换音色或关闭高光；精华版失败保留独立切片。
- **FFmpeg 字幕烧录能力**：高光切片与片头依赖 libass `subtitles` 滤镜。缓解：沿用 `run` 既有预检，缺失时在处理前失败并指出受影响阶段。
